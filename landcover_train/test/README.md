# Land-Cover Pseudo-Label Dataset (derived from OSCD)

## ⚠️ Important: read this before training anything

The source dataset (Onera Satellite Change Detection, OSCD) has **no land-cover
labels**. It only ships binary urban *change / no-change* masks for 24 Sentinel-2
image pairs. There is no water/urban/forest/agriculture/barren ground truth
anywhere in the original data.

The masks in this folder are **pseudo-labels generated by rule-based spectral
thresholding** (NDVI / NDWI / NDBI / BSI), not verified ground truth. They are a
standard way to bootstrap a segmentation model when no labeled land-cover data
exists, but expect real-world accuracy in roughly the 70–85% range, with the most
common failure modes being:
- **Urban vs. barren land confusion** (dry soil and pavement have similar spectral response)
- **Agriculture vs. forest confusion** at NDVI values near the 0.5 cutoff
- **Mixed pixels** at class boundaries (10m Sentinel-2 resolution)
- **Shadows / clouds** are not explicitly handled and may get misclassified

**Recommended before using this for a real model / publication:** manually spot-check
and correct a subset of masks, or cross-validate against a real product like
[ESA WorldCover](https://esa-worldcover.org/) or Dynamic World for the same tiles/dates.
This dataset is best treated as a way to get a ResUNet training loop working end-to-end,
then refine label quality afterward.

## Method

For each of the 24 AOIs, both time points (`imgs_1_rect`, `imgs_2_rect`, already
resampled to 10m resolution) were used — 48 image/mask pairs total.

Spectral indices computed from Sentinel-2 bands (scaled to ~0–1 reflectance):

| Index | Formula | Purpose |
|---|---|---|
| NDVI | (B08−B04)/(B08+B04) | vegetation vigor |
| NDWI | (B03−B08)/(B03+B08) | water |
| NDBI | (B11−B08)/(B11+B08) | built-up/impervious surface |
| BSI  | ((B11+B04)−(B08+B02)) / ((B11+B04)+(B08+B02)) | bare soil |

Classification rule (applied in priority order — first match wins):

```
NDWI > 0.10                              -> Water        (1)
NDVI > 0.50                              -> Forest        (3)
NDVI > 0.20                              -> Agriculture   (4)
NDBI > 0.05 and NDVI < 0.15              -> Urban          (2)
BSI  > 0.10                              -> Barren land   (5)
else                                     -> Other / Unclassified (0)
```

See `generate_landcover_labels.py` for the exact implementation — thresholds are
plain constants near the top of `classify()`, so you can tune them per-region if
a class looks over/under-represented in your spot checks.

## Folder structure

```
landcover_dataset/
├── images_rgb/                 # <aoi>_t<1|2>.png  - stretched RGB preview (B04,B03,B02)
├── images_multiband_npy/       # <aoi>_t<1|2>.npy  - float32 (H,W,4) = R,G,B,NIR, 0-1 scale
├── masks/                      # <aoi>_t<1|2>_mask.png - single-channel, pixel values 0-5 (TRAIN ON THIS)
├── masks_colored/              # <aoi>_t<1|2>_mask_color.png - RGB visualization for QA only
├── labels_summary.csv          # per-image class % breakdown, for sanity-checking outliers
├── generate_landcover_labels.py
└── README.md
```

`images_multiband_npy/*.npy` is what you'd feed a ResUNet (R,G,B,NIR — NIR helps a lot
for vegetation classes). `masks/*.png` is the corresponding label — load with
`np.array(Image.open(path))`, values are already the class IDs 0-5, no further
decoding needed. Use `masks_colored/` only to eyeball quality, not for training.

## Suggested ResUNet setup

- Input: 4 channels (R,G,B,NIR) from `images_multiband_npy/`
- Output: 6-class softmax (or `nn.CrossEntropyLoss` in PyTorch) over `masks/`
- Images vary in size per AOI (see `labels_summary.csv`) — random-crop to a fixed
  tile size (e.g. 256×256) for batching, standard for this dataset in change-detection
  literature too
- With only 24 AOIs × 2 timepoints, patch-based random cropping + augmentation
  (flips/rotations) is essential to get enough training samples
- Given both timepoints of the same AOI are highly similar scenes, consider grouping
  by AOI (not by sample) when doing your train/val split, to avoid leakage
